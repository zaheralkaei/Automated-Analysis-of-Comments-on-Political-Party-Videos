# Automated Analysis of Stance, Rhetorical Techniques, and Divisiveness in YouTube Comments on Political Party Videos

**Master's Thesis — Zaher Alkaei**

An end-to-end Python pipeline for collecting, annotating, and classifying German-language YouTube comment threads from political party channels. The pipeline covers data collection through modelling, explainability, and visualisation, structured as numbered steps that run in sequence.

---

## Repository Structure

```
.
├── 01_channel_enumerator.py       # Step 01 – discover channel video IDs
├── 02_german_scraper.py           # Step 02 – scrape comments via YouTube API
├── 03_anonymizer.py               # Step 03 – anonymise usernames
├── 04_username_fixer.py           # Step 04 – resolve username inconsistencies
├── 05_relation_builder.py         # Step 05 – build parent–child comment pairs
├── 06_topic_filter.py             # Step 06 – BERTopic-based topic detection
├── 07_topic_mapper.py             # Step 07 – map videos to climate / migration
├── 08_pair_creator.py             # Step 08 – stratified sampling of comment pairs
├── 09_annotation_tool.py          # Step 09 – Streamlit UI for manual annotation
├── iaa_analysis.py                # Inter-annotator agreement between the two manual annotators
├── conflict_resolver.py           # Streamlit UI to resolve manual annotation conflicts into gold_standard.jsonl
├── 10_llm_annotator_gold_eval.py  # Step 10 – LLM annotation of gold subset + LLM annotation evaluation
├── 11_llm_annotator_rest.py       # Step 11 – LLM annotation of remaining pairs
├── 11_dedup_annotations.py        # Deduplicate/retry incomplete Step 11 LLM annotations
├── 12_thread_scores.py            # Step 12 – aggregate pair scores to thread level
├── 13_overview_report.py          # Step 13 – corpus statistics report
├── 14_feature_engineering.py      # Step 14 – extract theory-driven + embedding features
├── 15_shallow_learners.py         # Step 15 – train/evaluate LR, RF, SVM, XGB
├── 16_bert_finetuning.py          # Step 16 – fine-tune gbert and xlmr-base
├── 17_llm_evaluation.py           # Step 17 – evaluate open-weights LLMs via OpenRouter
├── 18_thread_classification.py    # Step 18 – thread-level controversy classification
├── 19_explainability.py           # Step 19 – SHAP, Layer Integrated Gradients, error analysis
├── 20_visualizations.py           # Step 20 – all figures for the thesis
├── 21_error_analysis.py           # Step 21 – confusion matrices across model families
├── prompts/                       # Annotation prompt templates (interaction, stance, techniques)
├── utils/                         # Shared helpers (JSONL I/O, API wrappers)
├── data_a_b/                      # Channel A/B: video metadata (01_channel_videos/) + pipeline outputs (02–05, not in repo)
├── data_c_d/                      # Channel C/D: video metadata (01_channel_videos/) + pipeline outputs (02–05, not in repo)
└── requirements.txt
```

Output directories (`06_bertopic_output/`, `07_filtered/`, `08_pairs/`, `09_manual_annotations/`, `10_llm_annotations/`, `11_llm_annotations/`, `12_thread_scores/`, `13_overview/`, `14_features/`, `15_shallow_results/`, `16_bert_results/`, `17_llm_results/`, `18_thread_results/`, `19_explainability/`, `20_visualizations/`, `21_error_analysis/`) are created automatically when each step runs.

## Data Availability

This repository ships the final annotated dataset and derived features used in the thesis (`08_pairs/`, `09_manual_annotations/`, `11_llm_annotations/`, `14_features/features.parquet` and `split_index.json`), plus channel/video metadata (`data_a_b/01_channel_videos/`, `data_c_d/01_channel_videos/`).

Not included (regenerable, but excluded for size and privacy reasons — see `.gitignore`):

- **Steps 02–05 outputs** (`data_a_b/`, `data_c_d/` subfolders `02_raw_scraped` through `05_relations`) — raw scraped comments contain real YouTube usernames before anonymization, and the full per-video corpus is several GB. Regenerate via Steps 02–05 (requires a `YOUTUBE_API_KEY`).
- **BERT/XLM-R embedding caches** (`14_features/*.npz`) — regenerated by Step 14.
- **Trained model artifacts** (`06_bertopic_output/bertopic_model`, `15_shallow_results/models/`, `16_bert_results/checkpoints/`) — regenerated by Steps 06, 15, and 16 respectively.

## Running a Step

Each script is self-contained and reads from the output of the previous step:

```bash
python 01_channel_enumerator.py
python 02_german_scraper.py
# ... and so on
python 20_visualizations.py
python 21_error_analysis.py
```

Steps 01–05 are run twice, once per dataset: set `BASE_DATA_DIR=./data_a_b` with the AfD `CHANNEL_A_ID`/`CHANNEL_B_ID`, run Steps 01–05, then switch `.env` to `BASE_DATA_DIR=./data_c_d` with the Linke channel IDs and rerun Steps 01–05 (see the commented alternatives in `.env.example`). Steps 06 onward process both `data_a_b/` and `data_c_d/` together.

After Step 09, two annotators each produce a `gold_standard_*.jsonl`. Run `iaa_analysis.py` to compute inter-annotator agreement, then `streamlit run conflict_resolver.py` to resolve conflicts into `gold_standard.jsonl` before continuing to Step 10. After Step 11, run `11_dedup_annotations.py` to retry any pairs with incomplete LLM annotations.

Steps 10, 11, and 17 require active API access and incur costs. All other steps run locally once the data is in place.
